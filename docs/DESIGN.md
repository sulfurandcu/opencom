# opencom 设计文档

版本 v0.0.0 ｜ 2026-10-17 ｜ 目录：`opencom/wpf/`

opencom 是 Windows 串口调试助手，用 **WPF + XAML + MVVM** 实现。

---

## 2. MVVM 架构

- `MainViewModel` 是唯一 ViewModel，暴露 `ObservableCollection<SendRow> Rows`、串口/显示参数、
  状态栏文本、全部 `[RelayCommand]`（添加/插入/删除/上移/下移/发送选中/循环/循环全部/
  清空/复制/保存/Shell 等）。
- 视图只做手势翻译（双击→发送/切格式/查看匹配关系、右键→动态菜单、Shell 按键→发送），业务全在 VM。
- 发送列表用 DataGrid：内容列与次数列是模板列里**常驻 TextBox**
  （`UpdateSourceTrigger=PropertyChanged`，点进格子即可输入）；格式/关系为只读计算属性列。
- 选中行样式：DataGrid 资源里覆盖系统高亮画刷为 240 灰底（模板触发器优先级高于普通样式，
  直接设 `DataGridRow.Background` 会被系统高亮盖住）。**选中只改背景，字体保持组色**：
  CellStyle 里用样式触发器把选中态 Foreground 重设为 `{Binding GroupColor}`
  （样式触发器优先级高于模板触发器，压住主题里 IsSelected→HighlightTextBrush 的覆盖）。
- 表头默认居中，仅"内容"列表头左对齐；格式/关系/次数单元格居中。
- 组颜色：`RebuildTriggers()` 按触发行序号从 12 色调色板取色，同一组同色。
- 单元格显示：`FormatLabel`/`RoleLabel` 是计算属性，底层字段变化时经
  `OnFormatChanged`/`OnRoleChanged` 钩子手动发通知（漏掉这个会导致"双击格式格没反应"）。

## 3. 串口读写架构（核心）

### 3.1 读线程

```csharp
while (!ct.IsCancellationRequested) {
    try { n = port.Read(buf, 0, buf.Length); }      // 同步读 + ReadTimeout=500ms
    catch (TimeoutException) { continue; }           // 超时轮询，正常
    catch (InvalidOperationException) { break; }     // 端口已关闭
    catch (OperationCanceledException) { break; }    // 关闭中止挂起读，别误报 PortGone
    ...
}
```

**必须用同步 `Read`，不要用 `BaseStream.ReadAsync`**：CH340 等 USB 串口上异步读会
立刻返回 0 字节，循环空转上百次后驱动报 "I/O operation has been aborted"，被误判成
串口断开（"COM7 打不开"的根因，实测 2026-10-17）。

### 3.2 TX 队列 + 写线程

- `Write()` 非阻塞入队 `BlockingCollection<byte[]>`（上限 64KB，满则丢弃并记日志），
  UI 永不因写超时卡住。
- 写线程消费队列，**每次写前按实际数据长度和波特率重算超时**：

```
WriteTimeout = max(500ms, 数据字节数 × 10位 × 1.5余量 ÷ 波特率)
```

  例：8192 字节 @ 115200 → ~1.1s；@ 9600 → ~12.8s。小数据反馈快，慢波特率不误报。
- 写失败记日志 + 状态栏提示"发送失败（设备未响应或对端未连接）"，不影响后续发送。

### 3.3 异步关闭

- `Close()` 立即置逻辑标志 `_open=false`、取消令牌、完成队列，**实际的 `port.Close()`
  放后台线程**——刚发过数据时 SerialPort.Close 会等挂起的写排空（最长写超时），同步关
  会让 UI 卡顿（"发送后关闭很慢"的根因）。
- `Open()` 调用 `Close()` 后**等待关闭任务完成**再开新端口——否则排队的关闭任务会在
  新端口打开之后执行，把新端口又关掉（"打开了还提示请先打开串口"的竞态，日志里连续
  多次打开无关闭记录）。
- `IsOpen = _open && _port is { IsOpen: true }`——逻辑标志保证异步关闭期间状态即时反映。
- **缓冲清理**：关闭前与打开后都 `DiscardInBuffer/OutBuffer`——端口关着时设备可能还在发，
  数据堆在驱动缓冲里，不清理的话重新打开会先吐出一堆过时数据。
  打开新会话时同步清空应用侧接收状态（行缓冲/待显队列/CR·UTF-8 归一化状态）。

## 4. 触发匹配引擎（TriggerEngine.cs）

**行级匹配（用户决策）**：匹配只在完整的一行内进行——RX 数据先入行缓冲
（上限 8KB，超出丢最旧），一行收完才喂引擎、喂完即重置状态，**跨行的数据拼不成
匹配**。行由 **CR/LF** 或**静默断行**（3 字节时间，下限 10ms）界定，行结束符本身不参与匹配。
命中后发送目标（触发行）内容；显示顺序：先显示完整匹配帧，再显示 [TX] 响应。
**触发总开关 + 全局延时**：发送面板底部"触发"开关（选中=开启，关闭时只丢弃缓冲不做匹配，
延时中的待发也取消）；旁边"延时(ms)"输入框对全部触发统一生效（0=立即），随配置持久化。

三种匹配模式（针对完整的一行）：

- **CONTAINS（包含）**：行内朴素扫描，行内任意位置出现模式即命中（可多次）。
- **EQUALS（相等）**：**整行与模式完全相等**才算命中——行内不滑窗，
  否则触发回复（模式+附加字节）会在行内偏移处再次命中，两个触发端互相回发形成环路。
- **PREFIX（前缀）**：行以模式开头即命中，失配后收缩到最长合法前缀（KMP 退化版）。

行为细节：
- 单字符 hex 放**高**半字节（"A" → 0xA0）。
- 匹配行默认完全相等。
- **内容编辑即时生效**：提交时 `TryCompileContent` 同步刷新匹配行的模式（曾出现过
  编辑后不触发、重启才生效的 bug——模式没跟着刷新）。
- 行增删/移/角色改动后 `Rebuild` 重建编译缓存，丢弃在途半匹配。
- 行缓冲/匹配与显示暂停无关：暂停只暂停显示，匹配照常运行。

设置流程：先设触发行 → 右键"触发匹配"子菜单列出所有触发行显式关联 →
"匹配方式"子菜单选择完全相等/前缀/包含。**无组数上限**（用户要求）。
**连带处理**：取消触发行或删除触发行时，关联到它的匹配行一并取消标记；
插入/移动行时匹配行的关联目标跟着位移（`FixMatchTargets`）。

## 5. 接收显示管线

1. **TX 门控**：`Display.ShowTx` 默认关；Shell 键入（`ShellKey/ShellKeyRaw`）**永不显示**。
2. **暂停门控**：`RecvPaused` 时 RX 与 TX 都进待显队列，恢复时按序补显。
3. **前缀**：`[HH:mm:ss.fff] ` + `[RX] ` / `[TX] `（方向后统一一个空格）。
   Shell 模式下设备回显不加时标/方向前缀。
4. **格式**：`Display.Hex` 控制 HEX/ASCII（默认 HEX）；**Shell 回显永远是 ASCII**。
5. **ASCII 归一化**（`NormalizeAscii`）：
   - CR → 换行；`\r\r\n` 里冗余 CR 吞掉；裸 LF → 换行（跨块 `_prevCr` 状态）
   - Tab 保留；其余控制字符显示 `.`；UTF-8 不完整序列跨块续接（`_utf8Tail`）；非法字节 `.`
6. **TX 断行**：发送结束点已知，发完即断行；**TX 前先把未结束的行收尾**——
   否则触发场景下匹配帧刚写完、静默断行还没到，TX 会被挤进 RX 行且没有自己的
   [TX] 前缀；RX 不追加（换行由归一化产生）。
   **显示顺序**：触发命中时先显示本块 RX（完整匹配帧），再显示 [TX] 响应（用户决策）。
7. **静默断行**：超过 **3 个字节时间**没新数据即认为空闲、由定时器补换行
   （3×10位÷波特率，下限 10ms、轮询 10ms）。
   例：115200→10ms（下限）、9600→10ms（下限）、300→100ms。
   阈值越小越灵敏，但发送端"分块写"间隔超过阈值会被误断行（会切断行级匹配）。
8. 文本上限 512KB 截断；同屏内容**逐字**同步写入 `~/.opencom/opencom.txt`——换行同样由
   CR/LF 归一化 + 静默断行产生，不按接收块强制断行；清空接收窗口时若行未断，日志先补换行收尾。

## 6. 配置与日志

| 文件 | 位置 | 内容 |
|---|---|---|
| opencom.json | `C:\Users\<用户名>\.opencom\` | 串口参数 + 显示选项 + 触发选项（开关/延时）+ 发送列表（行内容/格式/角色/匹配模式/目标行/次数） |
| configs/\<名称\>.json | 同目录 configs/ | 命名配置（文件菜单"保存配置.../加载配置"） |
| opencom.log | 同上 | 运行日志（启动/退出含收发统计、打开/关闭串口含参数、发送失败、触发命中、循环发送、未处理异常） |
| opencom.txt | 同上 | 接收窗口数据（与显示逐字一致） |

退出时保存，启动时加载（旧配置缺"次数"字段时自动补默认 1）。命名配置：保存时弹对话框命名
（重名确认覆盖，文件名非法字符转下划线）；文件菜单"加载配置..."打开**配置管理对话框**——
列表列出全部命名配置，支持加载（双击列表项同效，**加载后自动关闭**）/**F2 行内重命名**
（Enter 提交/Esc 取消/失焦提交）/删除；串口打开时拒绝加载（参数只在下次打开生效）；
加载后经 `ConfigLoaded` 事件同步串口参数下拉框。行内编辑实现注意：焦点在列表内部转移
（条目→编辑框）不能算失焦提交，否则进入编辑框的动作会立刻取消编辑。

## 7. 功能清单

- **串口**：端口枚举（数字序）/打开/关闭、波特率 300-921600、数据位 5-8、校验、停止位、流控、
  DTR/RTS；打开后参数条禁用；断开弹提示；打开失败提示（含"请选择端口"守卫）。
- **发送列表**：添加/插入/删除/上移/下移（上限 200 行）；内容列与次数列常驻编辑；
  新行默认 HEX；HEX 校验失败回滚提示；次数列失焦校验非负整数（0=循环全部时跳过）。
  双击手势：格式格=该行 HEX/ASC 互切、格式表头=全部互切（解析失败行保持原格式）、
  触发表头=查看所有匹配关系、触发格（触发/匹配行）=查看该组匹配关系、次数表头=全部重置为 1。
  格式/触发/次数列禁止点击排序；组颜色；右键菜单
  （单次发送/循环发送/触发发送/触发匹配（关联触发行）/匹配方式/取消标记/取消全部）。
- **发送**：发送选中、双击内容格发送、循环发送（行号/次数/间隔对话框，0=无限）、
  **循环发送全部**（每行一个"次数"列单独配置，0=跳过；对话框设轮数（0=无限）/行间间隔/轮间间隔；
  含触发/匹配行；两个循环各管各的停止）、触发匹配发送（**总开关 + 全局延时(ms)**，
  关闭时不匹配、延时中的待发取消）；未开串口提示"请先打开串口"。
- **接收**：HEX/ASCII 显示（底部按钮+菜单同步，按钮固定文字"ASCII"、状态用选中背景表示，
  勾选=ASCII）、时间戳、方向、发送数据开关、暂停/恢复监视（补显）、清空/复制/保存文本。
- **Shell 模式**：键入即发、Tab 发 `0x09`、回车 EOL（CRLF/CR/LF 可设，默认 CR）、
  Esc 退出、Ctrl+C 发 `0x03`；回显无前缀且永远 ASCII；接收区禁用输入法。
- **状态栏**：端口状态（"COM7 115200 已打开（监视已暂停）"语义）、RX/TX 计数。
- **二级窗口**：循环发送参数、循环发送全部参数、查看匹配行（表头/触发格双击进入）、配置管理（加载/重命名/删除命名配置）。

## 9. 关键设计决策（用户拍板）

| 决策 | 说明 |
|---|---|
| 无触发组数上限 | 不限制匹配-触发组数量 |
| 保存原始数据 | 移除（用户认为不必要） |
| 写超时 | 按数据长度+波特率自适应 |
| 行级匹配 | 一行收完才喂引擎，跨行不拼（2026-10-17） |
| EQUALS 整行相等 | 行内不滑窗，防触发环路（2026-10-17） |
| 触发显示顺序 | 先显示完整匹配帧，再显示 [TX] 响应（2026-10-17） |
| 静默断行阈值 | 3 字节时间、下限 10ms、轮询 10ms（2026-10-17 由 5 字节收紧） |
| 循环发送全部 | 每行独立次数列 + 轮数/行间/轮间间隔（2026-10-17） |
| 两个循环各管各的停止 | 循环运行中另一个按钮无动作（2026-10-17） |
| 新增行默认 HEX | 2026-10-17 |
| 图标 | opencom.png（窗口）+ 多尺寸 ico（EXE）；播放/停止/暂停为 Path 矢量图标按钮 |
| 端口刷新 | 重建列表时保留当前选中（修复 PortName 变 null） |
| 发送菜单 | 已移除（功能由按钮/双击手势覆盖） |
